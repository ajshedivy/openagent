   ```typescript
   const client = await getAgentOSClient()

   ```

   IMPORTANT: Check the actual SDK API for the health check method. It may be `client.health()`, `client.system.health()`, or similar. The RESEARCH.md flagged this as an open question. Inspect the SDK types (from Plan 01's type inspection) to find the correct method. If no health endpoint exists in the SDK, use `client.agents.list()` as a connectivity check instead (catching errors).

2. Import SDK error types from `@worksofadam/agentos-sdk`. The RESEARCH.md suggests `APIError` and `AuthenticationError` exist. Check actual SDK exports. Wrap the health check (and the `agents.list()` call) in structured error handling:

   ```typescript
   import { APIError, AuthenticationError } from "@worksofadam/agentos-sdk"
   // (adjust import names based on actual SDK exports)
   ```

   Error handling pattern:
   - `AuthenticationError` -> throw Error with message: "AgentOS authentication failed. Check your AGENTOS_API_KEY."
   - `APIError` -> throw Error with message including status code: "AgentOS connection failed ({status}): {message}"
   - Network/connection errors (e.g., ECONNREFUSED) -> throw Error: "Cannot connect to AgentOS at {baseURL}. Check that the server is running."
   - Unknown errors -> re-throw

   If the SDK does not export `AuthenticationError` as a separate class, check for `APIError` with status 401/403 instead:
   ```typescript
   if (error instanceof APIError) {
     if (error.status === 401 || error.status === 403) {
       throw new Error("AgentOS authentication failed. Check your AGENTOS_API_KEY.")
     }
     throw new Error(`AgentOS API error (${error.status}): ${error.message}`)
   }
   ```

3. Also wrap the `client.agents.list()` call in the same error handling pattern. If the health check passes but agents.list() fails, the user should still see a meaningful error.

4. The current code silently returns `{}` when baseURL is missing. With the SDK client, `getAgentOSClient()` throws on missing baseURL. Wrap the entire loader body in a try/catch that handles the "not configured" case gracefully (return `{}` to allow other providers to load, but log a warning):
   ```typescript
   async loader(getAuth, provider) {
     try {
       const client = await getAgentOSClient()
       // health check + discovery...
     } catch (error) {
       if (error instanceof Error && error.message.includes("not configured")) {
         // AgentOS not configured - this is fine, other providers may be used
         return {}
       }
       // For auth/API/connection errors, log warning and return empty
       // (provider system should not crash if one provider fails)
       console.warn(`AgentOS provider failed to initialize: ${error}`)
       return {}
     }
   }
   ```

IMPORTANT: The error handling should be resilient. The plugin loader should NOT crash the entire application if AgentOS is unavailable. Catch errors, log them as warnings, and return `{}` so other providers continue to work. The key is that the ERRORS are meaningful, not that they crash the app.
