<task type="auto">
  <name>Task 2: Refactor plugin to use SDK client, remove custom fetch wrapper</name>
  <files>
    packages/opencode/src/plugin/agentos.ts

  <action>
Refactor `packages/opencode/src/plugin/agentos.ts` to use the SDK client instead of manual fetch:

1. Remove the `fetchAgents()` function entirely (lines 92-117 in current file). This is the custom fetch with manual Authorization header injection that SDK-03 requires removing.

2. In the `loader` function:
   - Import and call `getAgentOSClient()` from `../provider/sdk/agentos/agentos-client`
   - Replace `fetchAgents(baseURL, apiKey)` with `await client.agents.list()` (the SDK client method)
   - The SDK returns typed agent responses. Map SDK agent response objects through the existing `agentToModel()` function. If the SDK response type differs from the current `AgentOSAgent` interface, adapt the mapping (the SDK type names may be different -- check the actual SDK types).
   - Keep the `agentToModel()` function for now (Phase 8 will fully migrate it), but update its parameter type if the SDK response shape differs from `AgentOSAgent`.

3. Remove the custom fetch wrapper from the loader return value. Currently the loader returns:
   ```typescript
   return {
     baseURL,
     apiKey,
     async fetch(request, init) { ... } // THIS MUST BE REMOVED
   }
   ```
   The SDK handles auth internally. The return value should still provide `baseURL` and `apiKey` (the provider factory still needs them until Phase 9 migrates the language model), but the custom `fetch` wrapper that injects `Authorization` headers MUST be removed. Return:
   ```typescript
   return { baseURL, apiKey }
   ```

4. The `apiKey` and `baseURL` resolution logic in the loader can be simplified since `getAgentOSClient()` handles resolution internally. However, the loader still needs `baseURL` and `apiKey` to return them for the provider. Keep the resolution logic in the loader but remove the `if (!baseURL) return {}` early-return since the SDK client will throw a clear error if baseURL is missing.

5. Keep the `agentToModel()` function and `methods` array unchanged. The `AgentOSAgent` type import may need updating if the SDK provides an equivalent type, but for backward compatibility in Phase 7, keep using the custom type and cast if needed.

IMPORTANT: Do NOT modify `agentos-language-model.ts` or `agentos-provider.ts` in this task. Those are Phase 9 concerns. The language model still uses its own fetch/FormData for streaming -- that is expected and correct for Phase 7.
  </action>

    - `packages/opencode/src/plugin/agentos.ts` calls `client.agents.list()` for agent discovery
    - TypeScript compiles without errors: `cd packages/opencode && bun run typecheck`
