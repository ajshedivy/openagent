   ```
   to:

   ```
   Remove the old comment about casting SDK type.

3. Update the `agentToModel` function signature (~line 125-126). Change:
   ```typescript

     agent: AgentOSAgent,
     baseURL: string,
   ```
   to:
   ```typescript
   function agentToModel(
     agent: AgentResponse,
     baseURL: string,
   ```

4. Handle the SDK type difference for `agent.id`: SDK `AgentResponse` has `id?: string | null` (optional), while the old custom type had `id: string` (required). The function already uses `agent.id` in several places. Since the caller (`client.agents.list()`) always returns agents with `id` populated, and line 86 already does `agent.id!` in the loop, add a non-null assertion OR an early guard. Preferred approach -- add a guard at the top of `agentToModel`:
   ```typescript
   if (!agent.id) return null
   ```
   And update the caller loop to skip null results:
   ```typescript
   for (const agent of agents) {
     const model = agentToModel(agent, baseURL)
     if (model && agent.id) {
       provider.models[agent.id] = model
     }
   }
   ```
   Update the return type of `agentToModel` to include `| null`.

   Alternatively (simpler, per user decision from Phase 7 that casting is acceptable during migration): use non-null assertion `agent.id!` in the places where `id` is used within `agentToModel`, since the API always returns `id`. This is acceptable because Phase 11 will handle final type tightening. Use the guard approach if it's cleaner; use `!` assertions if the guard would bloat the code. Use your judgment.

5. Handle `agent.name`: SDK has `name?: string | null`, old type had `name: string | null`. The function already uses `agent.name || agent.id` which handles null. The optionality (possibly undefined) is also handled by `||`. No change needed.

6. Handle `agent.model`: SDK has `model?: ModelResponse | null` where `ModelResponse = { name?: string | null; model?: string | null; provider?: string | null }`. The old custom type used `AgentOSModelInfo = { name: string; model: string; provider: string }` (non-optional fields). The `agentMetadata` in options stores `agent.model` which is read by the `/agno` hub's `AgentDetail` component as `{ name: string; model: string; provider: string } | null`. Since SDK's `ModelResponse` fields are optional, the hub component's type assertion in `dialog-agno.tsx` line 366 will still work (it casts via `as`). No change needed in the plugin -- the hub already handles this via its own type assertion.
