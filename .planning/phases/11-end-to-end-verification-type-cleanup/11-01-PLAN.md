**Step 1: Simplify AgentOSProviderSettings in agentos-types.ts**

The `AgentOSProviderSettings` interface has `baseURL`, `apiKey`, and `name` fields. However, `createAgentOS()` in `agentos-provider.ts` only uses `options.name`. The `baseURL` and `apiKey` fields are dead code -- the SDK client singleton in `agentos-client.ts` resolves these independently.

Replace the current AgentOSProviderSettings with a minimal type:

```typescript
/**
 * Provider factory options for createAgentOS().
 * Note: baseURL/apiKey are resolved by the SDK client singleton (agentos-client.ts),
 * not passed through provider settings.
 */
export interface AgentOSProviderSettings {
  /**
   * Provider name for identification
   * @default "agentos"
   */
  name?: string
}
```

The caller in `provider.ts` passes `{ name: model.providerID, ...options }` with type `any`, so removing fields is safe -- they'll just be ignored.

**Step 2: Add clear section documentation to agentos-types.ts**

1. **SDK Type Re-exports** (AgentResponse, ModelResponse) -- these satisfy TYPE-02

3. **Provider Configuration** (AgentOSProviderSettings) -- minimal factory options

Update the JSDoc comments on the tool confirmation types to explain WHY they exist (app state, not API response types) and reference the SDK types they extend conceptually (ToolCallData, RunPausedEvent).
