# Milestone v2.0: AgentOS SDK Migration

**Status:** SHIPPED 2026-02-07
**Phases:** 7-11
**Total Plans:** 9

## Overview

Replace all custom AgentOS API client code with `@worksofadam/agentos-sdk` and ensure full working agent support end-to-end. Eliminates ~1000 lines of custom fetch/SSE/types code in favor of the official SDK.

## Milestone Summary

**Key Decisions:**
- SDK `@worksofadam/agentos-sdk@0.3.0` chosen as sole API client (installed from GitHub, not npm)
- AI SDK bridge preserved (AgentStream -> LanguageModelV2StreamPart)
- SDK client uses singleton pattern with lazy initialization
- Config resolution: baseURL (config -> env), apiKey (auth -> env -> config)
- Provider factory passes SDK client getter (not raw config) to language model
- getClient field required in AgentOSConfig - SDK client is sole transport

**Issues Resolved:**
- Custom fetch wrapper removed - SDK handles auth internally
- ~160 lines of custom HTTP code eliminated from language model
- 270+ lines of legacy SSE event types and Zod schemas removed
- 37 lines of duplicate type definitions eliminated
- Debug logging (11 call sites) cleaned up

**Issues Deferred:**
- Teams/Workflows hub implementation (SDK makes future addition trivial)
- Full package rebrand (separate milestone)

**Technical Debt Incurred:**
- Non-null assertions for API-guaranteed fields (agent.id) acceptable during migration
- SDK installed from GitHub (not npm registry) - needs publishing
